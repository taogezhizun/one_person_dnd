# Product and Experience Design

本文是 `one_person_dnd` 的产品、交互和视觉设计基线。竞品事实、技术证据与一手来源见
[AI 单人文字 TRPG 产品与技术基准调研](research/2026-07-28-ai-solo-rpg-benchmark.md)。

## 产品定义

`one_person_dnd` 是一个由玩家拥有数据、由 LLM 担任 DM 的长期单人文字冒险运行器。
它不是缩小版 VTT，也不是聊天前端套壳。

玩家的核心循环只有一条：

```text
读当前局面 → 表达行动意图 → 看 DM 裁决与叙事 → 审查状态变化 → 继续
```

产品优势按优先级排序：

1. 玩家可以自由描述行动，建议选项只帮助起步，不替玩家作决定。
2. 角色、世界和剧情状态可见、可审查、可恢复，LLM 只能提出候选变化。
3. 长期上下文分层召回，并解释本回合实际使用或裁剪了什么。
4. 本地 SQLite 是权威存档；远程模型只是可替换的生成依赖。

“本地优先”在当前阶段准确表示 **local-owned / local-first data**：没有远程模型时仍能浏览和维护存档，
但不能继续生成 DM 回合；只有本地模型或离线玩法可用后，才能承诺完整离线游玩。

## 体验原则

### 1. Play first

故事、行动输入、最新建议和快速掷骰组成首要操作区。模型设置、原始 JSON、prompt 控制和诊断
放在模型页、系统标签或高级区，不能和“下一步行动”争夺注意力。

### 2. 玩家保留最终控制

- 建议行动点击后只填入输入框，玩家可改写再发送。
- `STATE_DELTA` 与 `THREAD_UPDATES` 先进入待确认队列，不能直接修改权威状态。
- 恢复存档前自动建立安全快照，完整回退叙事、记忆、剧情线和角色状态。

### 3. 生成错误是正常状态

流式失败、协议不完整、选项质量差和状态 JSON 错误都应有可解释的结果。界面不能用无限 loading
掩盖失败，也不能为了修复流式结果偷偷追加第二次阻塞模型调用。

### 4. 复杂度渐进披露

默认展示可读摘要和主操作；只有需要时才展开高级表单、原始 JSON、额外线索、诊断与配置。
空状态要告诉玩家下一步能做什么，而不是只报告“没有数据”。

## `/game` 信息架构

桌面主界面维持两栏，不增加第三个常驻栏：

```text
┌───────────────────────────────┬──────────────┐
│ 故事记录（剩余高度内滚动）    │ 角色          │
│                               │ 世界          │
├───────────────────────────────┤ 剧情          │
│ 行动甲板：最新建议            │ 系统          │
│ 行动输入 + 发送               │               │
│ 快速掷骰                       │               │
└───────────────────────────────┴──────────────┘
```

- 有历史的章节先读故事；空章节先看到行动输入。
- “行动甲板”把最新建议贴近输入区，历史建议留在对应回合并默认收起。
- 故事记录独立滚动，不能把输入区推出视口。
- 冒险面板默认约 400px，可在约 340–520px 调整；故事高度和面板宽度按 session 保存。
- 角色状态与待确认变更优先；世界事实和召回解释在世界标签；剧情线在剧情标签；技术诊断在系统标签。

本轮只验收 1280×720、1920×1080、2560×1440 桌面尺寸。移动端专项布局、亮色主题和第三栏不在范围内。

## 视觉方向

主题是“夜间冒险账册”：深色、安静、适合长时间阅读；信息密度来自清晰层级，不来自装饰。

| Token | Value | 用途 |
| --- | --- | --- |
| Obsidian | `#080b10` | 页面背景 |
| Slate | `#111820` | 主卡片与侧栏 |
| Parchment | `#e4d3b0` | 主要阅读文本 |
| Ember | `#c07643` | 玩家行动与危险提示 |
| Arcane Blue | `#7aa2f7` | 主操作、链接、焦点 |
| Verdant | `#8fd6b4` | 成功与安全状态 |

叙事使用 Georgia；界面使用 Avenir Next；机器可读内容使用 SFMono。交互必须保留可见焦点、
明确 label、`aria-live` 提交反馈和 reduced-motion 降级。避免 `transition: all`，避免让 placeholder
承担标签职责。

## 架构设计

继续采用 FastAPI + Jinja2/HTMX + SQLite 的模块化单体。当前规模没有拆微服务、引入消息队列或
复制 Foundry VTT 插件体系的收益。

一次回合分为三层：

```text
HTTP/SSE adapter
  → TurnPipeline（判定、上下文、DM、评估、持久化）
  → TurnPresenter（历史、非流式、流式共用的浏览器数据形状）
```

- `TurnPipeline` 拥有回合用例；路由只转换输入和处理 transport。
- `ContextPack` 是唯一 prompt 上下文入口，核心块优先，故事记忆先裁剪。
- `TurnPresenter` 是 Web 展示边界，统一 `dm`、掷骰、行动判定、诊断和待审状态。
- repository 是 SQL 边界；SQLite 使用外键、WAL、NORMAL synchronous 和 5 秒 busy timeout。
- HTMX 默认只请求同源，禁用响应脚本标签和动态表达式求值。

当前流式最终 DOM 仍由浏览器 renderer 生成，但输入数据已和服务器历史/非流式 partial 统一。
未来若继续收敛，应让服务器生成 canonical final partial，再由 SSE 只传事件和 HTML；这不是本轮必做项。

## 本轮三次有界优化

### Round 1：回合展示边界

- 新增 `web/turn_presenter.py`，统一历史、非流式和流式回合数据。
- `game.py` 回归 HTTP/SSE adapter，不再各自拼装 action/critic/response 数据。
- 对损坏的历史掷骰 JSON 做安全降级，不让一条旧记录阻断整个游戏页。

### Round 2：视口内核心循环

- `/game` 使用剩余视口高度，故事记录和冒险面板独立滚动。
- 最新建议收成横向“行动甲板”，输入与快速掷骰保持可见。
- 缩短 720px 高度下的非核心页头信息，不牺牲导航、状态与主要操作。

### Round 3：本地运行韧性

- SQLite 明确等待短暂写锁，减少连续表单提交造成的瞬时 `database is locked`。
- HTMX 增加同源与无动态代码默认值。
- 运行中不能只复制 WAL 主文件当作备份；应先停应用再复制，或使用 SQLite online backup。

Round 3 完成后停止本轮优化，不继续迭代视觉细节。

## 后续候选，不属于本轮

按价值从高到低：

1. 以服务器 partial 作为 SSE final 的唯一 DOM 来源，删除浏览器重复 renderer。
2. 增加可审计的 retry/edit/branch 变体，而不是覆盖旧 DM 输出。
3. 提供正式的 SQLite online backup、`quick_check` 和 campaign 导出。
4. 为远程模型调用显示清晰的隐私状态；如需正式支持非 loopback 部署，再增加认证边界，不能把现有 Origin/Fetch Metadata 防护当作登录认证。
5. 在固定连续性回归集证明收益后，再考虑 entity/location 召回和结构化 provider capability。

明确不做：战术地图、实时多人、市场、完整 5e 数据库、微服务拆分、第三常驻栏、无限视觉打磨。

## 验收合同

- `python -m compileall -q src/one_person_dnd`
- `python -m unittest discover -s tests -p "test*.py"`
- `/`、`/models`、`/saves`、`/game` 能在本地加载。
- 1280×720、1920×1080、2560×1440 无水平页面溢出，行动输入保持可达。
- 非流式 partial、流式 final 和历史回合展示的数据语义一致。
- 本轮仅形成工作区变更；提交、合并、发布和真实模型调用仍是独立授权边界。
